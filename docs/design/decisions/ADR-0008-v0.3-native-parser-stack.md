# ADR-0008 — v0.3 Native Parser stack и isolated PDF execution

**Статус:** accepted

## 1. Контекст

v0.3 должен дать практически полезное L1 Native Parsing для обычного web content, но не превратить Web Access в universal document processor.

Initial formats roadmap:

- HTML;
- plain text;
- JSON;
- XML;
- CSV;
- PDF native text.

Нужно выбрать libraries/execution profiles до Codex implementation.

---

## 2. Решение — parser stack

### HTML main content

```text
Trafilatura
```

Используется для main textual extraction/Markdown-like representation.

### HTML structural view

```text
lxml
```

Используется для:

- title/meta/canonical;
- links;
- headings;
- OpenGraph;
- JSON-LD script extraction;
- basic forms/structural metadata.

### XML

```text
defusedxml
```

или hardened parser path, использующий defusedxml-compatible protections.

External entities/network/unsafe DTD expansion запрещены.

### JSON

Python stdlib `json` + Pydantic/application bounded validation там, где нужен typed representation.

### CSV

Python stdlib `csv` + bounded textual decoder/dialect detection policy.

### Plain text/encoding fallback

- declared/format encoding first;
- UTF BOM/UTF standards;
- bounded `charset-normalizer` fallback where explicit encoding absent.

### PDF native text

```text
pypdf
```

только для чтения существующего PDF text layer/document metadata.

OCR/render-to-image не входит parser.

---

## 3. Почему `lxml`, а не отдельный selectolax baseline

Оба варианта технически пригодны.

Для initial stack выбирается `lxml`, потому что:

- зрелый parser/query API;
- хорошо подходит structural HTML/XML-adjacent tasks;
- Trafilatura ecosystem уже тесно связан с lxml-based document parsing;
- меньше разных tree semantics/dependencies в первой версии;
- performance ожидаемо достаточен при bounded document sizes.

Если benchmarks v0.9 или реальная нагрузка покажут structural parsing bottleneck, `HtmlStructuralParser` port позволяет заменить adapter на selectolax/Lexbor без изменения application output.

---

## 4. Main-content и structural parser разделены

Не требовать от Trafilatura быть источником всей структурной metadata.

Flow:

```text
raw HTML
├── Trafilatura → main text/Markdown
└── lxml        → structural metadata/links/JSON-LD
```

ContentApplication объединяет typed results согласно representation schema.

Один failure не должен заставлять скрыто переходить в Browser/L2.

Если structural extraction успешен, а main content отсутствует — это valid partial native result + diagnostics/hint.

---

## 5. HTML execution profile

Baseline:

```text
inline_bounded
```

при жестких input/output/deadline limits.

Если native parser crash/security evidence later требует isolation, profile может быть изменён конфигурацией/design без public API change.

---

## 6. PDF execution profile

Baseline:

```text
isolated_process
```

Причины:

- PDF parser может потреблять существенно больше памяти, чем размер файла;
- malformed/complex content streams могут быть CPU/memory-heavy;
- hard timeout/cancel должен уметь реально остановить parser;
- API process не должен погибать из-за одного PDF.

---

## 7. IsolatedProcessParserExecutor

v0.3 реализует минимальный reusable executor для riskier L1 parsers.

Не использовать обычный `ProcessPoolExecutor` как единственную isolation guarantee, потому что timeout/cancel Future не гарантирует остановку уже выполняющегося parser task.

Baseline model:

```text
parent Content process
→ materialize bounded private temp input
→ spawn short-lived parser subprocess
→ pass typed parser request
→ child parses
→ child writes bounded structured/text output temp/pipe
→ parent validates output
→ Content ingest derived representation
→ terminate/cleanup child/temp
```

---

## 8. Parser subprocess entrypoint

Отдельный internal entrypoint, например:

```text
python -m web_access.workers.parser_once
```

или equivalent executable module.

Он:

- не запускает FastAPI/FastMCP;
- не имеет DB/Redis/provider credentials;
- получает только bounded local temp input + parser ID/options;
- возвращает typed result/error;
- не имеет arbitrary command execution interface.

---

## 9. Process startup

Использовать fresh/spawned process, не `fork` inherited application state.

Это уменьшает риск наследования:

- DB sockets;
- Redis clients;
- auth secrets;
- logging context;
- event loops.

Short-lived process overhead для PDF принимается ради isolation.

Если v0.5 benchmarks покажут необходимость reusable isolated pool, это отдельное optimization design при сохранении same executor contract.

---

## 10. Hard timeout

Parent имеет parser-specific hard timeout меньше remaining operation deadline.

Если child не завершился:

```text
terminate
→ bounded wait
→ kill if required
→ cleanup temp
→ parser_timeout
```

Нельзя просто `future.cancel()` и оставить PDF processing в background.

---

## 11. OS resource limits

Production Linux child применяет available OS limits перед parsing:

- address-space/memory bound (`RLIMIT_AS`/эквивалент где надёжно работает);
- CPU time;
- file size/output temp limit;
- open files/process constraints при необходимости.

Container-level limits остаются defense in depth.

На Windows local development, где POSIX rlimits недоступны, сохраняются:

- input hard limits;
- wall timeout + process terminate;
- bounded output;

и документация честно отмечает weaker memory isolation.

---

## 12. Temp input/output

Temp paths:

- generated;
- private application temp root;
- не client filename;
- no path traversal;
- cleanup in success/failure;
- retention sweeper для crash leftovers.

Child не получает ContentStore root целиком.

---

## 13. Child output protocol

Не использовать pickle для IPC/result.

Использовать versioned JSON control/result + separate temp output file для большого text, если нужно.

Parent проверяет:

- schema version;
- parser ID/revision;
- output size;
- expected files under private temp root.

Derived ContentObject создаёт только parent trusted ContentApplicationService.

---

## 14. PDF initial limits

Exact numeric limits конфигурируются v0.3 implementation, но schema/policy должна иметь минимум:

- max raw bytes;
- max pages;
- max wall time;
- max child memory;
- max extracted output bytes/chars.

Нельзя использовать только file size как protection.

---

## 15. PDF image-only semantics

pypdf success с отсутствующим text layer:

```text
native text unavailable
```

а не parser failure.

Result:

- raw PDF ContentRef;
- page count/metadata where available;
- no text representation;
- warning/diagnostic;
- hint `advanced_processing_may_be_required`.

No OCR invocation.

---

## 16. PDF encrypted

Password-protected PDF:

- Inspection marks encryption;
- no brute force;
- v0.3 no password argument;
- Native Parsing returns `encrypted_content` rejection/diagnostic;
- raw PDF remains available.

---

## 17. HTML security

HTML parsers:

- do not execute JavaScript;
- do not fetch external resources;
- JSON-LD parsed as untrusted JSON data;
- links resolved/normalized only as metadata, not followed;
- output size/depth/count limits.

Main text remains untrusted content.

---

## 18. XML security

XML parsing baseline prohibits:

- external entities;
- network resolution;
- unsafe DTD/entity expansion;
- unbounded depth/size.

`defusedxml`/equivalent hardened parser tests include entity expansion fixtures.

---

## 19. JSON security/limits

JSON parser ограничивает raw bytes и, через post-parse traversal/policy где нужно:

- maximum depth;
- output representation size.

Не выполняет automatic schema inference/semantic flattening.

---

## 20. CSV semantics

CSV Native Parser возвращает bounded table representation.

Dialect detection:

- только bounded sample;
- delimiter allowlist;
- result содержит detected delimiter/encoding metadata;
- ambiguity/failure возвращает diagnostic, а не бесконечные retries разных encodings/dialects.

---

## 21. Encoding

HTTP declared charset/format-specific encoding имеет приоритет, если валиден.

Если отсутствует:

- BOM/UTF checks;
- `charset-normalizer` bounded fallback для plain text/HTML-like input.

Detected encoding сохраняется как observation with confidence/diagnostic if library provides it, но Content не утверждает perfect correctness.

---

## 22. Parser result schema

Каждый parser возвращает typed internal result:

```text
parser_id/revision
source format
representations[]
inspection additions
warnings
diagnostics
```

Не возвращает library-native object.

---

## 23. Parser IDs baseline

Предлагаемые stable internal IDs:

```text
html-main-trafilatura
html-struct-lxml
text-native
json-native
xml-native
csv-native
pdf-pypdf
```

Они являются internal/provenance IDs и не обязаны быть MCP enum.

---

## 24. Version pinning

Parser dependencies pinned через `uv.lock`.

Parser revision должен измениться, если upgrade/library/config способен существенно изменить derived representation.

Не полагаться только на package version как application parser revision: registry descriptor имеет собственную revision.

---

## 25. Tests

### HTML

- article;
- product-ish page;
- malformed HTML;
- JS shell;
- JSON-LD;
- huge links/scripts;
- no external fetch.

### XML

- valid;
- external entity;
- billion laughs/entity expansion;
- deep nesting;
- malformed.

### PDF

- native text;
- multiple pages;
- image-only;
- encrypted;
- malformed;
- large content stream;
- timeout child;
- kill/cleanup;
- output limit;
- temp cleanup after parent/child failure.

### CSV/text/JSON

- encodings;
- malformed;
- limits;
- dialect ambiguity;
- deep JSON.

---

## 26. Consequences

Плюсы:

- простой и понятный initial L1 stack;
- HTML roles разделены;
- PDF не угрожает API process напрямую;
- parser isolation reusable v0.5;
- no L2 creep;
- libraries hidden behind registry ports.

Минусы:

- PDF parse process startup overhead;
- две HTML processing libraries;
- cross-platform hard memory limit не одинаково силён;
- temp materialization добавляет I/O.

Trade-offs принимаются ради reliability/security.

---

## 27. Roadmap consequence

`IsolatedProcessParserExecutor` переносится из идеи «добавить в v0.5» в **v0.3 Content Core**, потому что initial PDF support уже требует process isolation.

v0.5 расширяет:

- parser set;
- isolation profiles;
- возможно reusable isolated pool после benchmark;

но не впервые вводит isolation abstraction.

---

## 28. Acceptance

1. Initial parsers ровно L1; no OCR/LibreOffice/VLM.
2. HTML main/structural roles separate.
3. XML hardened.
4. PDF pypdf runs isolated subprocess.
5. Hard timeout реально terminates parser process.
6. Child no DB/Redis/provider secrets.
7. IPC no pickle.
8. Temp cleanup/reaper handles crashes.
9. Image-only PDF returns no-native-text + hint, not failure/OCR.
10. Parser outputs typed/versioned/provenanced.
11. Public MCP/REST contract independent of concrete parser library.

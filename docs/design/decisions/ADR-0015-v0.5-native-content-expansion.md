# ADR-0015 — v0.5 Native Content Expansion: direct format readers, без universal conversion

**Статус:** accepted

## 1. Контекст

После v0.3 Web Access уже умеет L0/L1 для HTML, text, JSON, XML, CSV и PDF native text.

v0.5 должна расширить практически полезные document/content families, но сохранить фундаментальный инвариант:

```text
L1 Native Parsing
≠
L2 conversion/OCR/rendering/semantic AI processing
```

Нельзя добавлять LibreOffice fallback, OCR или VLM только потому, что формат оказался сложным.

Также нельзя превращать parser registry в коллекцию десятков случайных dependencies без понятной responsibility/isolation model.

---

## 2. Решение — initial v0.5 families

v0.5 добавляет native support для следующих семейств.

### OOXML

```text
DOCX
XLSX
PPTX
```

### OpenDocument direct package readers

```text
ODT
ODS
ODP
```

### E-books / XML documents

```text
EPUB
FB2
```

### Vector/web image structure

```text
SVG
```

### Bitmap image L0 inspection

```text
JPEG/JPG
PNG
GIF
WebP
TIFF
```

### Audio technical metadata L0 — optional v0.5 capability

```text
MP3
FLAC
Ogg/Vorbis/Opus
WAV/AIFF
M4A/MP4 audio where supported by inspector
```

Это **не означает** transcription/media understanding.

---

## 3. OOXML libraries

### DOCX

Использовать:

```text
python-docx
```

Native representation включает bounded:

- document properties;
- paragraphs/headings/list-like structure where available;
- tables;
- hyperlinks/relationships where safely resolvable as metadata;
- headers/footers where parser supports them deterministically;
- embedded media inventory metadata, но не OCR содержимого картинки.

### XLSX

Использовать:

```text
openpyxl
```

в `read_only=True` baseline.

Native representation:

- workbook/sheet names;
- bounded cells/rows;
- formulas and/or cached values согласно explicit parser profile;
- merged-cell/sheet metadata where useful;
- no macro execution;
- no external workbook fetch.

Large workbooks must stream/iterate and stop at configured cell/row/output limits.

### PPTX

Использовать:

```text
python-pptx
```

Native representation:

- slide order;
- text-bearing shapes;
- tables;
- notes where reliably exposed;
- hyperlinks/basic shape metadata;
- image inventory metadata;
- no visual interpretation of diagrams/images.

Unsupported rich PowerPoint features remain honest limitations rather than reasons for rendering/LibreOffice fallback.

---

## 4. Macro-enabled and template OOXML

v0.5 **не обещает** full native support для:

```text
DOCM
XLSM
PPTM
DOTM
XLTM
POTM
```

Если container structurally readable выбранной library, L0 Inspection может определить family и macro presence, но:

- VBA/macros никогда не исполняются;
- macros не анализируются семантически baseline;
- extension не маскируется как plain DOCX/XLSX/PPTX без explicit capability evidence.

Поддержка отдельных macro-enabled formats добавляется только contract tests после проверки library behavior.

---

## 5. Почему не использовать LibreOffice для Office baseline

LibreOffice headless conversion является L2-style conversion process:

```text
format A
→ office application runtime
→ format B/PDF
→ parse
```

Это:

- тяжелее;
- расширяет attack/process surface;
- добавляет rendering/conversion semantics;
- не является direct native reading.

Поэтому v0.5 не запускает LibreOffice.

Legacy DOC/XLS/PPT остаются unsupported native formats, пока не будет отдельного безопасного direct parser design.

---

## 6. ODF: direct package reader

Для ODT/ODS/ODP baseline **не вводится обязательная odfpy dependency**.

Web Access реализует bounded `OdfPackageParser` поверх:

```text
zipfile-compatible package reader
+
existing hardened XML parser (defusedxml/lxml-safe profile)
```

Читаются только известные ODF package parts, например:

```text
mimetype
META-INF/manifest.xml
meta.xml
content.xml
styles.xml only when needed for semantic structure
```

Parser не пытается воспроизвести визуальный layout документа.

### ODT

Извлекаются:

- text paragraphs/headings;
- tables;
- metadata;
- links;
- basic list/section structure.

### ODS

Извлекаются:

- sheets;
- rows/cells;
- formulas as stored text/value metadata where safely available;
- repeated-row/cell constructs с hard expansion limits.

### ODP

Извлекаются:

- page/slide order;
- text elements;
- basic table/text structure;
- metadata.

No rendering/visual diagram interpretation.

---

## 7. ZIP/container security profile

OOXML/ODF/EPUB являются ZIP-based containers.

Нужен reusable `SafePackageReader`.

Requirements:

- max archive bytes;
- max entry count;
- max individual uncompressed entry;
- max total uncompressed bytes;
- compression ratio ceiling/zip-bomb protection;
- normalized member names;
- reject absolute paths/`..` traversal;
- no extraction arbitrary files to filesystem when in-memory/stream parse sufficient;
- symlink/special entries rejected/ignored according policy;
- no recursive nested archive expansion baseline;
- bounded XML depth/entity protections.

Package parser работает с logical members, а не `extractall()`.

---

## 8. EPUB

EPUB baseline реализуется прямым package parser, без mandatory EbookLib dependency.

Причины:

- EPUB является ZIP/container + XML/XHTML structure;
- для read-only L1 Web Access достаточно ограниченного стандартизированного subset;
- не нужен writer/manipulation API;
- уменьшается dependency/license surface.

Parser:

1. проверяет EPUB container/mimetype;
2. читает `META-INF/container.xml`;
3. находит package document/manifest/spine;
4. читает spine XHTML documents в порядке;
5. использует existing HTML/XML native parsing для chapter content;
6. извлекает metadata/table-of-contents where safely available;
7. не выполняет scripts/external fetch.

Images остаются child resource inventory, но не OCR/VLM.

---

## 9. FB2

FB2 является XML document family.

Parser использует hardened XML path и извлекает:

- title/author/document metadata;
- sections/headings;
- paragraphs;
- notes/links where deterministic;
- embedded base64 image inventory bounded by size, но не обязан materialize все images в отдельные ContentObjects baseline.

Entity/network expansion запрещены.

---

## 10. SVG

SVG рассматривается как XML-based vector document.

L1 может получить:

- title/desc;
- `<text>` content;
- links;
- dimensions/viewBox;
- metadata/accessibility attributes;
- bounded structural summary.

Web Access **не интерпретирует визуальный смысл path/shape diagram**.

Embedded scripts не выполняются.

External resources не загружаются parser-ом.

---

## 11. Bitmap image inspection

Использовать:

```text
Pillow
```

только для L0/bounded metadata/inspection.

Может возвращаться:

- format;
- width/height;
- frame count/animated flag;
- mode;
- EXIF/XMP/basic metadata с redaction/normalization policy;
- orientation;
- bounded ICC/basic technical data where useful.

Не выполняется:

- OCR;
- image captioning;
- object detection;
- automatic pixel decode всей огромной image без необходимости.

Pillow decompression-bomb protections не отключаются.

Image inspection выполняется через isolated parser process profile, потому что image codecs/metadata могут быть resource-heavy и input недоверенный.

---

## 12. Audio technical metadata

Если включено в v0.5 build/profile, использовать:

```text
Mutagen
```

для direct metadata/stream info.

Можно получить bounded:

- format/container;
- duration;
- bitrate;
- sample rate;
- channels;
- tags/album/title/artist metadata;
- codec-specific technical fields normalized where practical.

Не выполняется:

- decoding audio в PCM ради анализа;
- transcription;
- speech/music classification;
- waveform analysis;
- loudness mastering analysis.

Media metadata parser также идёт через isolated profile baseline.

---

## 13. Почему не ffprobe baseline

`ffprobe` мощнее и покрывает больше media containers, но добавляет большой external FFmpeg binary/runtime dependency.

Для v0.5 Web Access нужен только дешёвый L0 metadata subset, поэтому pure-Python/direct Mutagen поддержка предпочтительнее.

Если video/more-general media inspection станет реальной потребностью, `ffprobe` может быть добавлен отдельным ADR как isolated external inspector.

---

## 14. Video formats

MP4/WebM/MOV video не получают semantic parsing v0.5.

L0 identification может вернуть MIME/container/size из general Content Inspection.

Если Mutagen способен надёжно получить некоторые metadata конкретного compatible container, это не превращается в обещание generic video support.

Full video technical inspector отложен до отдельной capability decision.

---

## 15. Isolation profiles

v0.5 расширяет `NativeParserDescriptor.execution_profile`.

### `inline_bounded`

Допустим только для low-risk text/XML-like parsers после hard raw-size limits:

```text
FB2
SVG
small direct XML/text operations
```

### `isolated_process`

Обязателен baseline для:

```text
PDF (уже v0.3)
DOCX
XLSX
PPTX
ODT/ODS/ODP
EPUB
bitmap images
media metadata
```

Причина — ZIP bombs, parser/library bugs, memory amplification, complex package content.

OOXML/ODF/EPUB isolation не означает, что библиотека «опасна»; это общий trust policy для сложных binary/container inputs.

---

## 16. Isolated parser executor evolution

v0.3 short-lived subprocess contract сохраняется.

v0.5 может оптимизировать startup через reusable isolated parser workers **только если**:

- каждый job всё равно имеет hard deadline;
- worker process можно terminate/recycle;
- memory/leak isolation bounded;
- no secrets;
- parser compatibility profile explicit;
- soak proves benefit.

Baseline implementation может оставить short-lived process per parse для correctness.

No shared parser process in Control Plane.

---

## 17. Parser output model

Все format readers возвращают общий typed internal result:

```text
parser_id
parser_revision
source_format
inspection additions
representations[]
structured sections/tables/pages/sheets where applicable
warnings
diagnostics
```

Library-native objects не выходят за infrastructure adapter.

---

## 18. Representation semantics

Цель L1 — не «идеально воспроизвести приложение», а дать machine-usable content.

Примеры:

```text
DOCX → document structure + text + tables
XLSX → workbook/sheets/cells
PPTX → slides + text/tables
ODT → text/tables
ODS → sheets/cells
ODP → slides/text
EPUB → ordered chapters + metadata
FB2 → sections/text
SVG → textual/metadata representation
image/audio → L0 technical metadata
```

Если layout/visual meaning lost, result честно содержит limitation/warning where relevant.

---

## 19. Formula semantics

Spreadsheet parser не вычисляет formulas.

Для XLSX:

- stored formula text может возвращаться;
- cached value может возвращаться отдельным field, если доступен;
- Web Access не утверждает, что cached value актуален;
- external links/formula evaluation не выполняются.

Для ODS аналогично: stored formula/value читаются как document data, не пересчитываются.

---

## 20. Macro/security semantics

Ни один parser:

- не исполняет macros;
- не выполняет embedded code;
- не открывает external links/resources;
- не запускает OLE objects;
- не materialize embedded executable автоматически.

Наличие macro/embedded object фиксируется inspection metadata/warning там, где это можно определить.

---

## 21. Parser registry

`ContentFormatRegistry` хранит versioned descriptors:

```text
format_id
media types/signatures
parser_id
parser_revision
execution_profile
supported representations
limits profile
capabilities
```

Public MCP не получает giant enum всех parsers.

REST diagnostics/provider-like inspection может показывать supported format capabilities authorised client-у.

---

## 22. Format detection

Extension является только hint.

Решение использует:

```text
declared MIME
magic/signature
container markers
package manifest/mimetype
parser capability
```

Например `.docx` должен реально быть compatible OOXML ZIP package.

Malformed/mismatched format возвращает diagnostic, а не parser selection loop по десяткам libraries.

---

## 23. Structured hints

Web Access может вернуть объективные hints:

```text
native_format_unsupported
advanced_processing_may_be_required
visual_content_not_interpreted
macro_content_not_executed
cached_formula_value_may_be_stale
```

Hint не рекомендует конкретный внешний proprietary/L2 tool без необходимости.

---

## 24. S3 ContentStore relationship

v0.5 parser expansion не должен зависеть от filesystem paths.

`ContentApplication` materializes bounded private parser input через ContentStore streaming abstraction.

S3-compatible adapter добавляется в той же версии отдельным implementation/design item, но parser contract остаётся backend-independent.

---

## 25. Fixture corpus

Обязателен committed/synthetic safe corpus без copyrighted bulk data:

- minimal valid files;
- malformed packages;
- truncated ZIP;
- zip bomb synthetic fixtures;
- huge repeated cell/row constructs;
- formulas/external links;
- macros presence fixtures where legally/safely constructible;
- image decompression-bomb fixture;
- weird metadata encodings;
- parser crashes/timeouts generated fixtures.

Real external corpus может использоваться optional/manual testing, не обязательный CI artifact.

---

## 26. Acceptance

1. Нет LibreOffice/OCR/VLM/transcription fallback.
2. DOCX/XLSX/PPTX имеют direct readers.
3. XLSX read-only/bounded iteration.
4. ODT/ODS/ODP используют safe package/XML parser без office runtime.
5. EPUB direct package/spine parsing, no script/external fetch.
6. FB2/SVG hardened XML.
7. Bitmap images только L0 metadata, no OCR.
8. Audio metadata — только technical/tags, если capability включена.
9. Complex containers/images/media идут isolated process profile.
10. ZIP bomb/path traversal/entity expansion fixtures blocked.
11. Macros/embedded code never executed.
12. Formula values never recomputed.
13. Public contracts independent of concrete libraries.
14. Unsupported/partial representation честно отражается diagnostics/hints.
15. Parser version/provenance стабильны и testable.

---

## 27. Не определяется

- legacy DOC/XLS/PPT support;
- DJVU/XPS/MHT;
- generic video metadata;
- ODG/ODB;
- macro-enabled OOXML full support;
- exact reusable parser worker optimization;
- L2 document service integration protocol.

Они добавляются только после отдельного use-case/security design.
